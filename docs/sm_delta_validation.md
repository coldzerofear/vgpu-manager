# delta 控制器重写验证报告（v13 战役）

对 `library/include/sm_delta.h` 中 `sm_delta_step()` 的全谱系仿真验证：新算法
对旧公式（HAMi-core 同源的 `sm²·thread·diff/2560` 步进，#274 病灶）在
**33000 个闭环场景中稳态精度与锯齿零负格**，冷启动双侧误差最差回退 1.4 个
利用率点（局限于 target≥74、旧公式"灌满到 100%恰好接近目标"的格）。
断言已固化为 CI 测试 `library/test/nogpu/test_delta_campaign.c`。

> 结论先行：新算法在稳态 MAE 上 31223 胜 / 1777 平 / **0 负**（误差聚合
> 1442937 → 175684，降低 8.2 倍）；p95 锯齿 27575 胜 / 5425 平 / **0 负**；
> 冷启动（双侧 MAE，前 300 tick）20935 胜 / 11908 平 / 157 负，负格全部
> ≤1.4 个点。仿真内数字；真机消融（`test/ablation`）仍是最终验收门。

## 1. 为什么重写

HAMi-core issue #274：旧步进 `sm²·thread·diff/2560` 随 SM 数平方增长，而令
牌池 `total = thread/SM × SM数 × 32` 只随 SM 线性增长。步进占池比 ∝ SM 数：

| 卡 | SM | 每 tick 步进占池比（diff=5 时） |
|---|---|---|
| MIG 1g 切片 | 7-14 | ~0.4-0.9% |
| RTX 4080 | 76 | ~4.6% |
| H100 | 132 | ~8.1% |
| 188 SM 级 | 188 | ~11.5%（diff 大时 >20%） |

大卡上桶在一秒内被灌满并钉死，限额从未生效——"大卡限不住"。仿真复现：
188 SM、hard_core=50、轻负载时旧公式平均利用率 **99.8%**（目标 50）。

进一步的发现（本轮仿真最重要的洞察）：**钉死的判据是步进"粒度"而非"幅度"
——只要最小步进大于负载每 tick 的消耗量，桶必然溢出**。消耗量是负载属性
而非卡属性，因此任何绝对值下限（包括线性化的 pool/N 下限）都是灌桶机制本
身。唯一在目标点自适应等于消耗量的量是 share 自己——这是 v13 乘性核心
`share·err/(damp·u)` 的由来。

## 2. 测试矩阵

**55 张真实显卡 × 限额 1–100 × 3 档负载强度 × 2 档反馈延迟 = 33000 格**，
每格新旧算法各跑一次完整闭环（预热 + 3000 tick 稳态窗口）。

### 2.2 负载与延迟

- 负载强度 R ∈ {pool/1500, pool/150, pool/15}（每 tick 消耗）：分别对应
  #274 描述的"几分钟才耗尽池"的轻网格、中等负载、重负载（15 tick 吞干全池）。
- 反馈延迟 ∈ {2, 4} tick：NVML 利用率窗口 + share 生效滞后。控制器只能看
  到延迟后的利用率——这是所有失稳模式的放大器。
- 闭环模型与 watcher 实现同构：桶每 tick 加 share（钳位于池容量）、负载最
  多取 R、util = 取到/R、控制器读延迟 util 后更新 share。故意苛刻（桶空时
  util 瞬时坍塌、离散 tick），绝对数字偏悲观，但新旧同受其苦，对比成立。

### 2.3 四维指标

1. **稳态 MAE**：预热后 3000 tick 的 |util−target| 均值——限得准不准。
2. **p95 锯齿**：稳态偏差分布的 95 分位——会不会频繁出现大锯齿。
3. **冷启动双侧 MAE**（前 300 tick）：爬得快不快，**且不以冲破限额为代价**。
   单侧"欠供"指标被弃用：旧公式在小目标格"赢"它的方式是灌到 100% 利用率
   ——用违反限额换吞吐不是胜利，双侧指标对这种违规定价。
4. **鲁棒性场景**（在 `test_delta_step.c` 中单测断言）：4/6-tick 延迟、
   轻→重负载中途切换、冷启动吞吐欠供预算。

## 3. 结果

### 3.1 主战役（test_delta_campaign.c，CI 断言）

| 指标 | 胜 | 平 | 负 | 断言 |
|---|---|---|---|---|
| 稳态 MAE（±0.5 平带） | 31223 | 1777 | **0** | 负 == 0 |
| p95 锯齿（±1 平带） | 27575 | 5425 | **0** | 负 == 0 |
| 冷启动双侧 MAE300（±0.5 平带） | 20935 | 11908 | 157 | 回退 ≤ 1.5 点 |

- 稳态误差聚合：1442937 → 175684（**8.2 倍**降低）。
- 冷启动 157 个负格最差 1.4 点（RTX3060 u=74 R/150 d4：26.6→28.0），全部
  位于 target≥74——旧公式的"灌到 100%"在高目标下碰巧接近目标值，属于其
  病灶的偶然副产品，且这些格的稳态与锯齿仍然是新算法胜。

### 3.2 单测层（test_delta_step.c）

代表性稳态 MAE（旧 → 新，2-tick 延迟）：

| 卡 | 限额 | 轻载 | 中载 | 重载 |
|---|---|---|---|---|
| MIG-7sm | 8 | 90.1→10.4 | 74.2→1.3 | 22.4→0.3 |
| RTX4080 | 50 | 50.0→10.0 | 49.8→1.3 | 46.5→0.4 |
| A100 | 30 | 69.8→10.5 | 68.2→1.3 | 56.8→0.3 |
| H100 | 80 | 20.1→11.6 | 21.0→1.3 | 23.9→0.4 |
| 188SM | 50 | 50.0→10.2 | 50.0→1.3 | 50.0→0.4 |

（轻载格新算法的 ~10 是模型量化粒度所致的悲观上界：R=pool/1500 时 util
只能取 0 或 100 的整数倍附近，任何控制器都无法在该离散度下做得更低。）

鲁棒性：#274 场景旧平均 util 99.8 → 新 60.0（目标 50，含悲观量化）；
4-tick 延迟 MAE 1.9；6-tick 延迟 3.2；轻→重切换后 MAE 0.4；冷启动欠供
12.8 个 tick 当量（预算 40，boot 跳升生效后远低于旧公式路径依赖的取舍点）。

## 4. v13 算法要点（每条都对应一个仿真暴露的失败）

| 机制 | 回答的失败 |
|---|---|
| 池相对、share 比例核心 `share·err/(damp·u)`，damp=6 | #274 的 sm² 灌桶；damp<6 在 6-tick 延迟下复利爆炸 |
| 种子 seed = total·5/81920 ≥ 1 | share=0 死锁；粒度低于轻网格消耗率（钉死判据） |
| 一次性 boot 跳升 total·u/6400 | 旧公式唯一真优势（首 tick 直达）；一次性故不参与振荡 |
| 饥饿阻尼 4（桶空时） | 中途重负载恢复慢；damp=2 在 6-tick 延迟爆炸（3→25+） |
| 平滑抗积分 `max(share/(share+bucket), err/100)` | 高目标回撤过狠引发下一次凹陷；硬带边界追逐（worst 格在带边游走） |
| 紧急下限 total·err/(u·64)，门控 err≥5 且 util>2u | 小限额血崩保护；门控防个位数目标的整数抖动误触 |
| u≥100 直通全池 | 100% 限额即无限额，控制器不应介入 |

淘汰路线的教训（详见头文件注释）：绝对步进下限本身就是灌桶机制（divisor
从 16384 扫到 163840 都改变不了钉死）；线性化 `pool/1024` 锚定 4080 在轻载
区同样钉死；远误差加速（damp 2 当 diff·2>u）在 6-tick 延迟下 MAE 3→45。

## 5. 局限与后续

- **仿真内结论**。模型不含 GAP 路径、idle 旁路、多进程共享桶的调度交错；
  真机消融 `test/ablation`（对拍 nvidia-smi 利用率）仍是验收门。
- 冷启动 157 个 ≤1.4 点的负格是双侧指标下的诚实残差，接受并已在 CI 中以
  1.5 点预算钉住。
- 常量可调面保留：`CUDA_SM_DELTA_INCREMENT_DIVISOR`（种子粒度）与
  ramp floor divisor（紧急下限）仍从环境变量读取并钳位，战役即默认值下打的。
